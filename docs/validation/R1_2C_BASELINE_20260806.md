## 2. 关键实现事实

- **Saba 每帧 `UpdatePhysicsAnimation` 都会对每个刚体调用
  `SetActivation(true)`**，而 `btRigidBody::setMotionState` 会把 motion
  state 的 transform **读回**刚体。因此 Restore 必须把 active motion
  state 恢复到 from-start 路径在 canonical 边界的精确值，否则下一步从
  错误姿态起算（N=1 时表现为 ~1e-3 的速度分叉）。
- **canonical 边界的 motion state 值**：
  - `motionFrame == 0`：PrepareFrameZero 直接
    `SyncActiveMotionStateToBodyTransform()`，motion state == body COM；
  - `motionFrame > 0`：Bullet `synchronizeSingleMotionState` 在
    `m_localTime == 0`（latency interpolation 开启）时写入
    `integrate(interpolationWorldTransform, interpolationVelocities,
    -fixedTimeStep)`；
  - 不能对 frame 0 也走 `integrateTransform`：即使角速度为零，指数映射
    后的 `safeNormalize` 也会扰动四元数 1 ulp，破坏位级等价。
- **`RebuildCollisionWorldDeterministic` 会销毁并重建 ground proxy**，
  Saba `MMDFilterCallback::m_nonFilterProxy` 仍指向旧 proxy（悬垂）。
  重建后必须重新挂载新 ground proxy，否则部分刚体（其 mask 不含
  ground 组）会静默丢失 ground 碰撞，等价性矩阵在 N>0 时失败。
- **cold-step 语义**：`StepFrameExact` 每帧清理 contact manifold 与
  solver history，使 from-start 与 restore 两条路径都以冷状态起步；
  这是 restore 路径（Phase 4 清理）与 from-start 路径保持一致的先决
  条件。**裁决（2026-08-07）：正式接受 Cold Canonical Boundary 作为
  R1.2 唯一确定性 Profile**，并写入总契约 §5；保留 warm-start 的
  `PreserveAcrossFrames` 档位是后续扩展，不在 R1.2 契约内。
- **构造参数 VMD identity**：`Initialize()` 加载构造参数传入的 VMD 时
  现在同步写入 `vmdFileHash` / `hasMotion`（与 `LoadMotion()` 一致），
  否则跨 VMD Checkpoint 拒绝会被静默绕过。
- **Hash 失败语义**：`BuildFrameStateHashes` 现在返回
  `TimelineStatus`；捕获失败时把三个 `valid` 显式置 false 并返回失败
  状态（`DeterminismHashes::valid` 默认是 true，`{}` 会伪造有效零
  hash），CreateCheckpoint 与 Restore Phase 5 都会先检查该状态。
- **FollowBone 一帧滞后伪影（实现发现）**：Saba 的 after-physics 骨骼在
  `SetActivation(true)` 读取 kinematic 刚体时仍持有上一帧姿态，导致
  from-start 边界上的 FollowBone 刚体变换滞后一帧（VMD 动画下
  不可由 Restore 复现）。修复：canonical 边界在 after-pass 后对
  FollowBone 刚体重新执行 `SetActivation(false)` 读取节点姿态，使边界
  刚体变换 == 当前帧动画姿态；该值被写入 Checkpoint 后 Restore 的
  `EvaluateAnimationFrameOnly + ResetCanonicalNoStep` 可精确复现。
  该修复只改变边界记录的 FollowBone 刚体值，不改变下一帧物理输入。
- **after-physics 求值只执行一次（实现发现）**：R1.2C 恢复路径在
  `EvaluateAnimationFrameOnly(frame) + ResetCanonicalNoStep` 后直接调用
  `RestorePhases`，由 Phase 6 执行唯一一次 after-pass；在恢复前再跑一次
  会对 IK 模型造成二次求解漂移。
- **frame 0 无物理写回（实现发现）**：`motionFrame == 0` 时 Restore
  Phase 6 跳过 `ReflectGlobalTransform` 与 `CalcLocalTransform`——
  from-start 的 frame 0 是 PrepareFrameZero 边界，从未跑物理、也没有
  写回；反射/重算会改变骨骼姿态，破坏 IK 模型（如蕾米埃尔）的
  checkpoint pose 等价性。
- **三实例等价性测试是防假绿的**：baseline（fresh from-start）、source
  （生成 checkpoint）、diverged（先跑 30 帧再 restore）必须是三个独立
  实例；任何两实例共享状态都会让测试失去意义。
- 非法 target（`target < N`、`== UINT64_MAX`）在 Restore 之前拒绝；
  CreateCheckpoint 要求三个状态 Hash 全部有效；
  Replay 途中失败 → Poisoned。

## 5. R1.2 Complete 收尾记录（非阻断技术债）

- **BeginAnimation/EndAnimation 生命周期对称**：恢复路径把动画求值拆成
  before/after 两段（`EvaluateAnimationFrameOnly` +
  `PublishAfterPhysicsPose`），当前实现保证 Begin/End 配对，但缺少专门
  的对称性断言/测试。后续在 R1.3 的 Profile/后端治理中补一条
  “求值生命周期配对”回归测试。
- **动作末帧语义措辞**：“超过动作末帧”的正确语义是**动画采样保持末帧
  姿态**（Pose/Vertex 保持、物理继续推进），而不是“所有最终 Pose 都
  静止”。无 VMD 时 Pose 不变只是特例；R1.3 文档与测试命名应统一按
  “动画采样保持末帧”表述，避免误导。
